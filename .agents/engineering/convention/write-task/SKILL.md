# Record a task

Read [the shared record contract](../../resources/problem-records.md). Follow its repository selection
and reconciliation procedure. Record the requested work, purpose, scope, owner, priority, dependencies,
source links and an observable completion condition. Use the provider's task template and validation;
preserve evidence and state unknown details explicitly.

Read any existing task, parent feature, goal, session or PR before creation. Repeated requests update
the same task and retain its stable identity. Link a substantial implementation plan from the item;
keep live backlog state in the selected tracker. Update the item as work proceeds, attaching delivery
links and actual completion evidence before closure. Recording alone does not authorize starting work.

Without a selected provider, use the repository's declared task/backlog convention. If none exists,
retain the request in the current task context and ask for its intended owner; do not invent a second
queue or adopt a tracker. Employer-specific work item creation remains with its authorized tooling.

# Explain only the code

A guide exists so its reader can read the code it quotes. Every sentence passes one test: does the
reader need it to read this code?

- Explain only code that exists at the current revision. No planned code, future milestones, or rules
  with no code behind them. When a milestone adds code, add its chapters then, never before.
- Give each point the fewest sentences that carry it: what the code does and means now. No history,
  no rationale for the choice made, no rejected alternatives.
- Never restate what another file owns: the plan, the roadmap, the learning process, the agreed
  standards, the knowledge record.
- No quizzes, glossaries, comparison tables, callout boxes, reading lists or other apparatus unless
  the reader asks for them.
- A comparison with a language the reader knows is one inline phrase, used only when it is the
  fastest route to the point.
- When code changes, update the chapters that quote or describe it in the same change.

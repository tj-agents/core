# The harness owns capability

Every capability an agent has here (skills, hooks, statuslines, permission grants, repo trust
boundaries) ships from a tj-agents marketplace plugin or a repo's own committed harness file
(`.agents/repository-harness.json`, a project-scope `.claude/settings.json` generated by
`machine:bootstrap-capabilities`). None of it belongs hand-typed into a user-scope profile
(`~/.claude/settings.json`, `~/.claude/hooks/*`, `~/.claude/CLAUDE.md`): that config does not travel,
so a fresh machine with the same plugins installed silently behaves differently from this one.

A permission grant ships as a PreToolUse hook that inspects the exact command and calls
`hook_runtime.grant()` (the `harness_grant.py` pattern), never as a `permissions.allow` entry typed into
a profile. A hook, statusline, or skill lives in the owning plugin's manifest. A repository's own trust
boundaries and command allowlist live in that repository, not copied by hand into every machine that
touches it.

The irreducible exception is the bootstrap minimum: `enabledPlugins` and `extraKnownMarketplaces` must
exist locally to load anything else, plus genuine machine-only facts (a filesystem path) and this
session's own model/effort/voice/UI preference. Everything else found in a user profile is a defect to
migrate, not a setting to leave alone.
